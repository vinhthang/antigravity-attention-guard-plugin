## 1. Overview & Root Cause Summary

Auditing live SQLite ledger traces (`~/.gemini/antigravity/attention_guard.db`) and ecosystem diagnostics (`scripts/system_audit.py`) across `antigravity-attention-guard-plugin` and `spec-driven-plugin` identified five lifecycle and telemetry defects:

1. **Defect 1 — Subagent Premature `send_message` Completion While Background Tasks Remain `RUNNING` (`waiting_for_dependents`) (`REQ-027`)**:
   - In subagent `b9ffd136-e386-495a-9c41-dcab32ab85df`'s transcript, `run_command` backgrounded `task-276`, `task-282`, and `task-288`. Instead of ending its turn to wait for genuine `SYSTEM` `<SYSTEM_MESSAGE>` task completion events, the `flash` model hallucinated `<system_message>...Task id ".../task-282" finished...</system_message>` inside its own `MODEL` `PLANNER_RESPONSE` text, killed its internal timer tasks, and called `send_message(status="completed")` to the Primary Agent while `task-282` and `task-288` were still running.
2. **Defect 2 — Missing `send_message` Subagent Re-Dispatch Ledger Tracking & Unenforced 300s Watchdog on Primary Agent `Stop` (`REQ-028`)**:
   - When the Primary Agent (`3b9c8b9a-bbb4-4e27-9f7f-55705b2cd55d` in turn `216`, or `39e408bd-...` in turns `236`, `272`, `300`) reused an existing idle subagent (`bf74d99d-00bc-4db5-b584-067686697c35` / `b9ffd136-...`) via `send_message`, `inject-rules.py` and `record-tool-result.py` (`matcher: "invoke_subagent"`) did not run. Consequently, no `WORK_PREPARED` or `HANDOFF_ACCEPTED` events were emitted, `work_items` remained `COMPLETED` under the initial turn (`103`), parent turn `216` closed immediately with `{"active_work": false}` while the subagent executed 12 commands (`14:45:49`–`14:47:34`), and the subagent's `Stop` hook dropped `WORK_TERMINATED_OK` (`cursor.rowcount == 0`).
   - Additionally, on Primary Agent `Stop` (`attention-check.py`), when `active_count > 0` or uncompleted non-daemon background `run_command` tasks exist, `attention-check.py` unconditionally returned `{"decision": "allow"}` without verifying that a `schedule` watchdog timer (`Timer:`) had been armed since the last wakeup.
3. **Defect 3 — False-Positive `spec-gate.py` Rejection When Subagent Prompts Reference `~/.gemini/` Plugin Symlinks (`REQ-029`)**:
   - In `spec-gate.py` (`extract_prompt_workspaces`), every `/...` path in the `invoke_subagent` prompt is passed through `Path(p_str).resolve()` and checked for `docs/specs/INDEX.md`. Referencing `/Users/thanghoang/.gemini/config/plugins/attention-guard/schemas/executor-payload.json` resolved via symlink to `/Users/thanghoang/github/antigravity-attention-guard-plugin` and triggered false-positive spec-gate rejections when working in other repositories.
4. **Defect 4 — 190x Token Telemetry Divergence (`attention-refresh.py` vs `session_stats`) & Unused `turns` Table (`REQ-031`)**:
   - `attention-refresh.py` calculates `total_tokens = os.path.getsize(transcript_path) // 4` over raw `transcript.jsonl` bytes (including JSON serialization framing, full internal `thinking` traces, and pre-compaction history), inflating `session_refresh_state.last_refreshed_tokens` up to `6,027,196` tokens (or `85,388` tokens after 3 turns) and writing false pre-compaction `session_checkpoint.md` files on every refresh trigger. Meanwhile, `session_stats` (`31,612` tokens) only recorded `invoke_subagent` chars in `record-tool-result.py`.
   - Furthermore, `CREATE TABLE IF NOT EXISTS turns` in `scripts/ledger.py` had `0` rows across 448 closed turns because `insert_event()` never updated `turns`, and `is_subagent()` called `insert_event(..., "WORK_CLAIMED")` / `"RUNNING"` on every subagent tool call instead of only on initial token claim.
5. **Defect 5 — `surface_validator.py` Custom Rule File Autotrigger & `google-cloud-developer` Surface Audit Failure (`REQ-032`)**:
   - `scripts/system_audit.py` failed (`exit 1`, `Overall Valid: False`) because `google-cloud-developer` uses `rules/google-cloud-discovery.md` (without `rules/AGENTS.md`) and did not explicitly mention its 4 bundled skills (`gcloud`, `google-cloud-recipe-auth`, `google-cloud-recipe-onboarding`, `retrieving-developer-knowledge`), while `autotrigger()` in `scripts/surface_validator.py` hardcoded `rules/AGENTS.md` instead of falling back to the plugin's existing `rules/*.md` file when `rules/AGENTS.md` is absent.

## 2. Normative Requirements (EARS Syntax)

### `REQ-027` — Subagent Background Task Fence on `send_message` & Synthetic System-Message Prevention
- **WHEN** a subagent (`is_sub == True`) invokes `send_message` (`send_message` or `default_api:send_message`), **THE** `enforce-delegation.py` hook **SHALL** inspect the subagent's parsed transcript (`parse_transcript`) for uncompleted, non-daemon background `run_command` tasks (`active_bg_tasks`) and **SHALL** deny `send_message` if any background command task has not yet received a genuine `SYSTEM` `SYSTEM_MESSAGE` completion/cancellation event or an explicit `GENERIC` `Task "<id>" cancelled.` event.
- **Acceptance Criteria**:
  - `parse_transcript(transcript_path)` in `scripts/common.py` extracts `active_bg_tasks: list[str]` containing task IDs spawned by `GENERIC` steps (`Tool is running as a background task with task id: <id>`) whose `Task Description:` does not start with `Timer:` or `Cron:` and whose originating `run_command` tool call did not set `IsDaemon: true`.
  - A task ID in `active_bg_tasks` is removed **only** when a step with `source == "SYSTEM"` and `type == "SYSTEM_MESSAGE"` contains `sender=<task_id>` or `Task id "<task_id>" (finished|was canceled|was cancelled)`, or when a `GENERIC` step contains `Task "<task_id>" cancel(l)?ed.`.
  - Synthetic `<system_message>` text emitted inside a `MODEL` `PLANNER_RESPONSE` step does **not** clear `active_bg_tasks`.
  - Calling `send_message` from a subagent while `active_bg_tasks` is non-empty returns `{"decision": "deny", "reason": "..."}` listing the active task IDs and instructing the subagent to wait for `<SYSTEM_MESSAGE>` completion or call `manage_task(Action="kill", TaskId=...)`.
  - `rules/EXECUTOR.md` explicitly prohibits fabricating `<system_message>` tags or calling `send_message` while background command tasks (`task-*`) remain running.

### `REQ-028` — Subagent `send_message` Re-Dispatch Tracking & Primary Agent Watchdog Gate on `Stop`
- **WHEN** the Primary Agent (`is_sub == False`) dispatches work to a subagent via `send_message` (`Recipient` matching a subagent conversation ID and `Message` containing a valid JSON handoff payload), **THE** plugin **SHALL** reactivate/upsert the subagent's `work_items` record (`status = 'ACTIVE'`) for the current `(parent_conv_id, parent_turn_id)` and transition the turn FSM to `State.EXECUTION_ACTIVE`; and **WHEN** the Primary Agent attempts to stop its turn (`attention-check.py`) while in-flight subagent work (`active_count > 0`) or uncompleted Primary Agent background command tasks (`active_bg_tasks`) exist without an active `schedule` timer (`active_timers_since_wakeup`), **THE** `attention-check.py` hook **SHALL** return `{"decision": "continue", "reason": "..."}` requiring the Primary Agent to arm a 300s `schedule` watchdog timer.
- **Acceptance Criteria**:
  - Primary Agent `send_message` (`PreToolUse` in `enforce-delegation.py` and `PostToolUse` in `record-tool-result.py` via `hooks.json` matcher `"invoke_subagent|send_message"`) updates/inserts the recipient subagent's `work_items` row to `status = 'ACTIVE'`, `parent_conv_id = conv_id`, `parent_turn_id = str(turn_id)`, `step_idx = str(step_idx)` and records `WORK_PREPARED` and `HANDOFF_ACCEPTED` events for `(conv_id, str(turn_id))`.
  - `is_subagent()` in `scripts/common.py` resolves `parent_conv_id` and `parent_turn_id` from the subagent's `work_items` record when available so subsequent subagent `Stop` events (`WAITING`, `WORK_TERMINATED_OK`) update the re-dispatched parent turn rather than the historical initial turn, and only emits `WORK_CLAIMED` / `RUNNING` on initial token claim (`newly_claimed == True`).
  - `parse_transcript(transcript_path)` tracks `active_timers_since_wakeup: list[str]`, adding timer IDs when a `GENERIC` step spawns `Task Description: Timer:...` (or a `PLANNER_RESPONSE` step invokes `schedule` / `default_api:schedule`), removing them when explicitly cancelled (`Task "<id>" cancelled.`), and resetting prior wakeup timers whenever a new `USER_INPUT` or `SYSTEM` `SYSTEM_MESSAGE` step arrives.
  - On Primary Agent `Stop` (`attention-check.py`), if `active_count > 0` or `len(active_bg_tasks) > 0`, and `len(active_timers_since_wakeup) == 0` (unless `AGY_REQUIRE_WATCHDOG_ON_STOP == "0"`), `attention-check.py` returns `{"decision": "continue", "reason": "..."}` (bounded by `MAX_STOP_REJECTIONS`) instructing the Primary Agent to arm `schedule(DurationSeconds=300, TimerCondition="any")` or terminate hung subagents/tasks.

### `REQ-029` — Exclude `~/.gemini/` Plugin Symlink Paths in `spec-gate.py` Prompt Workspace Extraction
- **WHEN** `extract_prompt_workspaces()` in `/Users/thanghoang/.gemini/config/plugins/spec-driven-plugin/scripts/spec-gate.py` scans `invoke_subagent` prompt text for file paths, **THE** function **SHALL** ignore paths whose lexical (pre-symlink-resolution) path resides under `~/.gemini/` (such as `~/.gemini/config/plugins/.../schemas/executor-payload.json`) and strip trailing punctuation before path resolution so read-only plugin references do not resolve via symlinks into plugin development repositories and trigger false-positive spec-gate rejections.
- **Acceptance Criteria**:
  - An `invoke_subagent` prompt targeting `/Users/thanghoang/github/oci` (which has an active `In-Progress` specification) while referencing `/Users/thanghoang/.gemini/config/plugins/attention-guard/schemas/executor-payload.json` and `payload_validator.py` extracts only `/Users/thanghoang/github/oci` in `mentioned_workspaces` and returns `{"decision": "allow"}`.
  - An `invoke_subagent` prompt that lexically targets `/Users/thanghoang/github/antigravity-attention-guard-plugin/scripts/enforce-delegation.py` directly still resolves `/Users/thanghoang/github/antigravity-attention-guard-plugin` and enforces `verify_active_specification()`.

### `REQ-031` — Active Context Token Telemetry Calculation, `session_stats` Synchronization & `turns` Table Lifecycle Tracking
- **WHEN** `parse_transcript(transcript_path)` parses a JSONL transcript and `attention-refresh.py` evaluates context token volume, **THE** plugin **SHALL** compute `active_context_chars` from actual step `content` and `tool_calls` payloads (excluding `thinking` reasoning traces and JSONL framing, and resetting across compaction steps while preserving raw file-size fallback for non-JSONL synthetic test files), synchronize `session_stats.total_session_chars`, and maintain turn lifecycle rows in the SQLite `turns` table.
- **Acceptance Criteria**:
  - `parse_transcript(transcript_path)` returns `active_context_chars: int` (sum of `len(content)` and serialized `tool_calls` across valid JSON steps since the latest compaction step, excluding `thinking` fields) and `has_valid_json_steps: bool`.
  - In `scripts/attention-refresh.py`, when `has_valid_json_steps` is `True`, `total_tokens` is computed as `active_context_chars // 4` (instead of `os.path.getsize(transcript_path) // 4`) and synchronized into `session_stats` via `ledger.sync_session_chars(session_id, active_context_chars)`; when `has_valid_json_steps` is `False` (e.g., raw byte test fixtures), it falls back to `os.path.getsize(transcript_path) // 4`.
  - `Ledger.insert_event()` upserts `(f"{actor_id}_{turn_id}", status, now)` into `turns` when `WORK_PREPARED` (`status = 'EXECUTION_ACTIVE'`), `STOP_REQUESTED` (`status = 'STOP_REQUESTED'`), and `TURN_CLOSED` (`status = 'CLOSED'`) events are recorded, and `Ledger.prune()` deletes `CLOSED` turns older than `retention_seconds`.

### `REQ-032` — Custom Rule File Autotrigger Fallback & Ecosystem Surface Audit Remediation
- **WHEN** `autotrigger()` in `scripts/surface_validator.py` repairs missing skill triggers for a plugin whose `rules/` directory contains a custom rule file (e.g., `rules/google-cloud-discovery.md`) instead of `rules/AGENTS.md`, **THE** function **SHALL** target the existing `rules/*.md` file and **THE** `google-cloud-developer` plugin's `rules/google-cloud-discovery.md` **SHALL** include trigger references for its 4 bundled skills so `scripts/system_audit.py` passes with 0 errors.
- **Acceptance Criteria**:
  - In `scripts/surface_validator.py`, if `surface.autotrigger_file` (`rules/AGENTS.md`) is absent from `tree` but one or more `rules/*.md` files exist in `tree`, `autotrigger()` and `validate_plugin_surface(..., repair_triggers=True)` write repaired skill trigger lines into the first sorted `rules/*.md` file in `tree`.
  - `/Users/thanghoang/.gemini/config/plugins/google-cloud-developer/rules/google-cloud-discovery.md` includes trigger references for `gcloud`, `google-cloud-recipe-auth`, `google-cloud-recipe-onboarding`, and `retrieving-developer-knowledge`, and `rtk python3 scripts/system_audit.py` exits with code `0` (`Overall Valid: True`, `Total Errors: 0`).
